## Required research report format
Each domain report should include:
1. Research question and scope
2. Professional user personas and jobs-to-be-done
3. Current professional workflow and pain points
4. Common techniques and algorithms
5. Candidate libraries, engines, and services
6. Comparative evaluation: capability, performance, scale, licensing, security, maintenance, ecosystem, developer experience
7. Data flow and integration requirements
8. Failure modes and operational concerns
9. Alternatives considered
10. Recommendation with evidence and confidence
11. Open questions and validation experiments
12. Sources with publication/access dates

## Evidence rules
- Separate vendor claims from independent evidence.
- Prefer official documentation for API behavior and licensing, and independent benchmarks or practitioner evidence for performance.
- Do not infer that a library is best merely because it is popular.
- Record version numbers and license details when relevant.
- Treat recommendations as provisional until reviewed.
